# 11 接口契约（preload 暴露的全部函数）

本文件列出渲染进程能调用的**全部**主进程接口。规则：

1. 只实现本表里的函数。每一行写了“引入 WP”，只在那个 WP 实现它，不要提前做后面 WP 的行（“后面”按 06 第 1 节的执行顺序：WP-20 排在 WP-03 之后、WP-04 之前）。
2. 本表没有的接口一律不要新增。确实需要时，停下来在报告里提出，由总设计师修订本文件。
3. preload 只暴露本表的具体函数，不暴露 `ipcRenderer`，不暴露“传通道名就能调用”的通用函数。
4. 通道名规则：`la:<领域>:<动作>`，动作用小写短横线。函数 `vault.unlockWithRecoveryKey` 对应通道 `la:vault:unlock-with-recovery-key`，`app.getInfo` 对应 `la:app:get-info`，依此类推。
5. 一律用 `ipcMain.handle` / `ipcRenderer.invoke`，禁止 `sendSync`。主进程推给渲染进程的事件用 `webContents.send`，preload 用 `ipcRenderer.on` 包装成下表的 `onXxx(callback) → unsubscribe`，回调只收到数据参数（不把 `event` 传给页面）。
6. **返回值**：preload 原样返回主进程的结果对象，不抛异常：
   - 成功：`{ ok: true, value }`（下表“返回 value”一列就是 `value` 的形状）；
   - 失败：`{ ok: false, error: { code, message, retryAfterMs? } }`。`retryAfterMs` 只在 `E_THROTTLED` 时出现。
   - 错误码只用 02 第 6 节列出的那些。
7. 主进程每个处理函数的前两步固定：① 校验发送方（工作区通道只接受工作区窗口，密钥库通道只接受密钥库窗口，向导通道只接受向导窗口），不符合返回 `E_FORBIDDEN`；② 校验参数（类型、长度、枚举值），不符合返回 `E_INVALID_ARGUMENT`。

## 4. 数据形状

### 4.1 changeset（`workspace.applyChanges` 的参数）

```js
{
  generation: "gen-…",                         // 来自 workspace.load() 的 generation
  schemaVersion: 12,                           // 渲染进程当前的 CURRENT_SCHEMA_VERSION
  upserts: [{ collection, id, json }],         // json 是实体的 JSON 字符串
  deletes: [{ collection, id }],
  ui: { … }                                    // 整个 ui 对象；没有变化时为 null
}
```

### 4.2 workspace.load() 返回的 workspace

与浏览器版在内存里使用的对象完全同形：`{ schemaVersion, workspaceId, savedAt, folders, pages, dataSources, databaseItems, databaseViews, relations, syncedSources, attachments, people, pageTemplates, databaseTemplates, discussions, comments, ui }`（WP-16 起多一个 `pageVersions`）。

### 4.3 备份摘要 summary（`inspect` 返回）

```js
{ createdAt, platform: "desktop" | "browser", appVersion, formatVersion, schemaVersion,
  counts: { folders, pages, dataSources, databaseItems, attachments },
  assets: { count, totalBytes },
  vault: { included: boolean, itemCount: number | null },
  encrypted: boolean, fileName }
```

### 4.4 校验报告 report（`verify` 返回）

```js
{ ok: boolean, problems: [{ code, path, detail }], summary }   // problems 最多列 50 条；summary 同 4.3（读不到 manifest 时为 null）
```

`code` 取：`NOT_ZIP`、`BAD_ENCRYPTED_CONTAINER`、`MANIFEST_NOT_FIRST`、`BAD_MANIFEST`、`FORMAT_TOO_NEW`、`SCHEMA_TOO_NEW`、`BAD_PATH`、`MISSING_FILE`、`SIZE_MISMATCH`、`HASH_MISMATCH`、`BAD_JSONL`、`COUNT_MISMATCH`、`BAD_VAULT`、`EXTRA_FILE`（`EXTRA_FILE` 只是警告，不影响 `ok`）。

### 4.5 快照条目

```js
{ id: "<目录名>", createdAt, reason: "daily" | "pre-migration" | "pre-restore" | "pre-upgrade" | "manual" | "vault-reset",
  appVersion, schemaVersion, sizeBytes, includesWorkspace: boolean, includesVault: boolean }
```

### 4.6 定期备份设置 schedule

```js
{ enabled: false, folder: null, weekday: 0, hour: 20, keepLast: 8, includeVault: false, encrypt: false,
  lastRunAt: null, lastResult: null }       // weekday 0=周日…6=周六；lastResult: { ok, at, message } 或 null
```

### 4.7 密钥条目：摘要、详情、新建与修改

摘要（`list`、`createItem` 等返回）：

```js
{ id, type, title, tags, favorite, subtitle, host, updatedAt, expiresAt, hasTotp, deletedAt }
// subtitle：subtitleFieldId 指向的不敏感字段的值；host：第一个 url 字段的主机名
```

详情（`getItem`）：条目模型见 03 第 6 节；敏感字段被替换成 `{ id, label, kind, sensitive: true, masked: true, hasValue: true }`（没有 `value`）。

新建 `input`：

```js
{ type, title, tags: [], favorite: false, subtitleFieldId: null, expiresAt: null,
  fields: [{ label, kind, value, sensitive }] }       // 字段 id 由主进程生成（f_ + 8 位随机十六进制）
```

修改 `patch`（每个键都可省略；省略表示不改）：

```js
{ title, tags, favorite, subtitleFieldId, expiresAt,
  fields: [
    { id, label, kind, sensitive, value },            // 改成新值（新增字段不带 id）
    { id, label, kind, sensitive, keepValue: true },  // 保留原值（界面没有显示过这个敏感字段时用它）
  ] }
// 提供 fields 时，这个列表就是修改后的完整字段列表：没出现在列表里的旧字段被删除；列表顺序就是新顺序。
// 敏感字段的值被修改或被删除时，旧值写入 history（03 第 6 节）。
```

### 4.8 密钥库设置 settings

```js
{ autoLockMinutes: 5, clipboardClearSeconds: 30, lockOnMinimize: false, verifyBeforeReveal: false }
// autoLockMinutes 取 1、5、15、30、60 之一；clipboardClearSeconds 取 10、30、60、90 之一
```

### 4.9 密码生成选项 options

```js
{ mode: "random", length: 20, upper: true, lower: true, digits: true, symbols: true, excludeAmbiguous: false }
{ mode: "passphrase", words: 5, separator: "-", capitalize: false, appendNumber: false }   // WP-11
```
