# 05 时间脉络视图与“软件开发进程”模板

用户原话：“我还想有一个管理我软件开发进程的模版，就像 notion 一样的模板，它是一个时间排列的图一样。就像我们 PPT 经常用的那种时间脉络展示一样的模板。”

拆成两件事：

1. **时间脉络视图**（WP-09）：数据库的一种新视图，把记录按日期画成 PPT 风格的时间线。
2. **软件开发进程模板**（WP-10）：模板库里的一个内置模板，一键生成项目页面、两张数据库和若干视图，默认就是时间脉络。

## 1. 时间脉络视图长什么样

横向（v1 只做横向），风格是墨白的“幻灯片式时间脉络”（`12-视觉规范-墨白.md` 第 8 节，样子贴近 Notion：无衬线字体、灰色细线、圆角色条）。**以截图 `design/mobai/shots/timeline-light.png`、`timeline-dark.png` 为准**，原型地址 `design/mobai/prototype/index.html#view=timeline&mode=light`。从上到下：

视觉规定（数值都来自原型 `b.css` 的 “timeline” 一段）：

- **刻度**：每个刻度一条贯穿上下的 1 px 细竖线（`--mb-line`）；线右边 10 px、距顶端 4 px 处写刻度文字，按第 3 节规则 6 拆成三部分：数字 `--mb-sans` 600 26 px（年刻度 22 px），单位字（日、月、季度、年）紧跟在数字后面 2 px，15 px 500 `--mb-muted`；附注（年份或月份）在下一行、上面空 6 px，12 px `--mb-faint`。
- **主轴**：1 px `--mb-line-2` 横线；从左端到今天的部分是 3 px `--mb-ink` 的粗线，两端 2 px 圆角（今天不在范围内时：范围全在过去就整条 3 px，全在未来就整条 1 px）。
- **里程碑**：轴上的标记，形状按“标记属性”映射（第 2 节 `markerMap`）：菱形（12 px 的方块转 45°，2 px 圆角）、圆（12 px）、圆环（14 px 圆、3 px 描边）、方块（11 px，2 px 圆角）、重大节点（28 px 的 `--mb-accent` 实心圆，中间白色火箭图标 `IconRocket` 14 px，外面一圈 3 px `--mb-paper` 色的环，把主轴隔开）。日期已经过去的标记是实心（填 `--mb-ink`），还没到的是空心（填 `--mb-paper`，1.5 px `--mb-ink` 描边）；圆环始终空心。卡片都在主轴**上方**，分层交替（第 3 节规则 8–9），没有边框、没有底色：第一行日期（12 px `--mb-muted`），第二行标题（15 px 600 `--mb-ink`；重大节点用 `--mb-accent` 16 px），第三行副标题（12 px `--mb-faint`）；靠左的卡片文字右对齐。连线是标记正上方 1 px 的 `--mb-line-2` 竖线，从卡片顶端到标记。
- **阶段**：主轴下方 8 px 高、4 px 圆角的色条，按泳道往下排。颜色按 `fill`（第 3 节规则 7：有进度属性时是进度，没有时是已经过去的时间占比）分三种：`fill = 1` 已完成，整条 `--mb-u-green`；`0 < fill < 1` 进行中，从左到 `fill` 比例的部分是 `--mb-accent`，其余 `--mb-tag-blue`；`fill = 0` 未开始，整条 `--mb-tag-gray`。色条下方 7 px 写 14 px 600 `--mb-ink` 的阶段名，后面隔 8 px 跟 12 px `--mb-muted` 的副标题；色条太短时只画色条（规则 7），悬停时显示名称。
- **今天**：2 px `--mb-today` 竖线，从刻度文字下方（距顶端 64 px）到底部上方 26 px；竖线顶端一个 10 px 的 `--mb-today` 圆点；底部一个红色胶囊，左边离竖线 8 px：高 20 px、圆角 10 px、左右 7 px、`--mb-today` 底、白字 12 px，写“今天 M月D日”（日期 600）。
- **颜色**：默认只有灰阶、Notion 蓝（进行中的阶段、重大节点）、绿色（已完成的阶段）和红色（今天）。视图设置了“颜色属性”时，阶段色条和里程碑标记改用该选项的颜色：色条已完成的部分和标记用 `--mb-u-<颜色>`，色条其余部分用 `--mb-tag-<颜色>`；选项颜色是 `default` 时仍按上面的默认颜色画。重大节点始终是 `--mb-accent`。
- **悬停**：其他条目降到 40% 不透明度；弹出层（12 第 6 节“菜单 / 弹出层”）显示完整名称、日期范围、状态、进度。键盘焦点用 12 第 6 节的“焦点”（2 px 半透明蓝色外框）。
- 默认“适应全部”：整条时间线刚好铺满视图宽度。没有阴影、没有渐变（进行中的色条两段颜色是硬边，不是渐变过渡）。

## 2. 视图配置（`roadmap`；新增视图类型不需要迁移，schema v13 由 WP-10 的状态分组引入）

```js

  datePropertyId: null,        // 必填：日期属性（单日或范围）
  colorPropertyId: null,       // 可选：单选/状态属性，决定颜色
  markerPropertyId: null,      // 可选：单选属性，决定里程碑节点形状
  markerMap: {},               // { [optionId]: "diamond" | "circle" | "ring" | "square" | "major" }，未映射的用 "diamond"；界面名：菱形、圆、圆环、方块、重大节点
  subtitlePropertyId: null,    // 可选：卡片第二行显示的属性（如“版本”）
  progressPropertyId: null,    // 可选：数字或汇总属性，0–1 或 0–100，在阶段段上画进度
  scale: "auto",               // "auto" | "week" | "month" | "quarter" | "year"
  density: "comfortable",      // "comfortable" | "compact"
  showToday: true,
  zoom: 1,                     // 1 = 适应全部；>1 放大后可横向滚动；取值 1、1.5、2、3、4

```

`normalizeViewConfig("roadmap", …)` 要像其他视图一样补默认值、保留未知字段。`VIEW_REGISTRY` 新增 `roadmap: { label: "时间脉络", description: "像幻灯片一样按时间展示里程碑和阶段" }`。

**选项颜色色板**（单选、多选、状态的选项 `color` 字段，全产品通用）：`default`、`gray`、`brown`、`orange`、`yellow`、`green`、`blue`、`purple`、`pink`、`red`。其他值一律按 `default` 显示。界面上的颜色用 WP-20 已有的用户内容颜色变量（12 第 3 节）：`--mb-u-<颜色>`（文字和实色）、`--mb-u-<颜色>-bg`（区块底色）、`--mb-tag-<颜色>` 和 `--mb-tag-<颜色>-text`（选项标签的底色和文字），白天和夜间各有一套；`default` 用 `--mb-ink`（实色）和 `--mb-tag-default` / `--mb-tag-default-text`（标签）。不要再新建颜色变量。

## 3. 布局算法（纯函数，必须单测）

位置：`src/domain/roadmapLayout.js`。

```js
// 输入已经归一化好的条目，输出所有图形的坐标。不读 DOM、不读时间（now 由参数传入）。
export function layoutRoadmap({ entries, width, now, config }) → {
  domain: { start, end },            // 毫秒（UTC）
  unit,                              // "day" | "week" | "month" | "quarter" | "year"
  step,                              // 刻度步长（单位的倍数）
  axis: { x0, x1, y },
  ticks: [{ x, t, label }],
  today: { x } | null,
  phases: [{ id, x, width, lane, y, height, color, label, subtitle, labelVisible, subtitleVisible, progress, fill }],
  milestones: [{ id, x, level, align, past, marker, color, card: { x, y, width, height } }],
  levels,                            // 卡片用了几层（至少 2）
  lanes,                             // 阶段用了几条泳道（至少 1）
  height,
  unscheduled: [id, …],
}
// 条目来自 roadmapEntries(workspace, source, items, config)：
// { id, title, start, end|null, color, marker, subtitle, progress, statusLabel }
// start/end 是毫秒：日期字符串 "YYYY-MM-DD" 按 UTC 零点解析；带时间的按其本身的时刻。
```

规则：

1. **排序**：按 `start` 升序，相同时按 `id` 升序。输入顺序打乱，输出必须完全一样。
2. **分类**：`end` 存在且大于 `start` → 阶段；否则 → 里程碑。没有 `start` → 进 `unscheduled`，不画。
3. **时间范围**：设所有可画条目的最早 `start` 为 S、最晚 `end`（或 `start`）为 E、`span = E − S`。`span = 0` 时左右各留 7 天；否则左右各留 `max(3 天, 0.05 × span)`。`domain = [S − 留白, E + 留白]`。没有可画条目时返回空布局（`ticks: []`、`phases: []`、`milestones: []`），不报错。
4. **坐标**：`axis.x0 = 24`，`axis.x1 = width × zoom − 24`；时间到横坐标是线性映射。
5. **刻度**（`scale: "auto"` 时）：`maxTicks = max(2, floor((x1 − x0) / 110))`。按下面的顺序依次尝试候选，选**第一个**刻度数 ≤ `maxTicks` 的；都不满足就用最后一个：
   1. 每 1 天、每 2 天、每 3 天（UTC 零点，且 `floor(t / 86400000)` 能被步长整除）；
   2. 每 1 周、每 2 周（UTC 周一零点，且从 1970-01-05 起的周序号能被步长整除）；
   3. 每 1 月、每 2 月（UTC 每月 1 日零点，且 `年 × 12 + 月(0–11)` 能被步长整除）；
   4. 每 3 月（即季度：1、4、7、10 月 1 日），单位记为 `quarter`；
   5. 每 6 月（1、7 月 1 日），单位记为 `month`、步长 6；
   6. 每 1 年、2 年、5 年、10 年（1 月 1 日，且年份能被步长整除）。
   刻度数 = 落在 `[domain.start, domain.end]` 内（含两端）的刻度时刻个数。`scale` 指定为某个单位时，只在该单位的候选里按同样规则选（季度只有一个候选）。
6. **刻度文字**：日与周写 `M月D日`（周用那个周一的日期）；月写 `M月`，但第一个刻度和跨年后的第一个刻度写 `YYYY年M月`；季度写 `YYYY Q1`…`YYYY Q4`；年写 `YYYY年`。画的时候用同一个文件导出的 `splitTickLabel(label)` 拆成 `{ numeral, unit, note, small }`：`M月D日` → 数字 `D`、单位 `日`、附注 `M月`；`M月` → 数字 `M`、单位 `月`、附注 `""`；`YYYY年M月` → 数字 `M`、单位 `月`、附注 `YYYY`；`YYYY Qn` → 数字 `n`、单位 `季度`、附注 `YYYY`；`YYYY年` → 数字 `YYYY`、单位 `年`、附注 `""`。只有年刻度 `small: true`（数字用 22 px，第 1 节）。
7. **阶段泳道**：贪心区间分配——按排序后的顺序依次放进第一条不冲突的泳道。两段首尾相接（前一段的 `end` 等于后一段的 `start`）不算冲突。所有泳道都在主轴**下方**：泳道 k 的色条 `y = axis.y + 36 + k × 56`、`height = 8`。`label` 是标题、`subtitle` 是副标题；`labelVisible = width ≥ 48`，`subtitleVisible = width ≥ 160`。`fill`：`progress` 不是 `null` 时等于 `progress`；否则等于 `(now − start) / (end − start)`，限制在 0–1。
8. **里程碑的层和方向**：按排序后的顺序处理，第 i 个（从 0 起）优先的层是：`i` 为偶数时层 1，奇数时层 0（层 0 离主轴最近）。卡片宽度固定（舒适 184 px，紧凑 148 px）。`align: "start"`（卡片在连线右边）时卡片的横向区间是 `[x + 10, x + 10 + 宽度]`；`align: "end"`（卡片在连线左边）时是 `[x − 10 − 宽度, x − 10]`。依次尝试（优先层, start）、（优先层, end）、（另一层, start）、（另一层, end）、（层 2, start）、（层 2, end）、（层 3, start）……选**第一个**同时满足两条的：区间在 `[axis.x0, axis.x1]` 之内；和同一层已经放好的卡片不重叠（两个区间相距不到 8 px 也算重叠）。卡片宽度大于 `axis.x1 − axis.x0 − 10`（容器极窄）时不尝试，直接用（优先层, start），卡片左边界 `axis.x0`。`past = start ≤ now`。
9. **竖直位置**：卡片高度舒适 64 px、紧凑 48 px，层与层之间 12 px。`levels = max(2, 用到的最大层 + 1)`；`axis.y = 96 + levels × (卡片高度 + 12) + 8`（顶部 96 px 留给刻度文字）；层 L 的卡片 `card.y = axis.y − 18 − 卡片高度 − L × (卡片高度 + 12)`；`card.x` 是第 8 条区间的左端。连线是 `x` 处的 1 px 竖线，从 `card.y` 到 `axis.y − 6`。
10. **高度**：`lanes = max(1, 用到的泳道数)`；`height = axis.y + 36 + (lanes − 1) × 56 + 44 + 48`（最下面 48 px 放“今天”的文字）。没有可画条目时 `levels = 2`、`lanes = 1`，其余同第 3 条。
11. **今天**：`showToday` 为真且 `now` 在 `domain` 内时才返回 `today`。
12. **性能**：500 个条目布局 < 50 ms。

WP-09 的 AC 里给出了刻度规则的标准答案（总设计师用这套规则实算）。

## 4. 交互

| 操作 | 结果 |
| --- | --- |
| 悬停节点、卡片或阶段段 | 高亮该条目及其连线，显示完整名称、日期范围、状态、进度 |
| 点击 | 打开该记录的页面（与其他视图一致，用现有 `onOpenItemPage`） |
| 拖动里程碑节点（水平） | 改日期，按天吸附；松手才写入；页面锁定时不可拖 |
| 拖动阶段段（水平） | 开始与结束一起平移，保持时长；按天吸附 |
| 键盘 | `Tab` 按时间顺序在条目间移动焦点；`Enter` 打开；`Esc` 取消正在进行的拖动 |
| 工具条 | “适应全部”“放大”“缩小”“今天”（放大后滚动到今天）、“导出” |
| 导出 | 固定 16:9 画布：逻辑尺寸 1920 × 1080（按宽度 1920 重新布局，顶部 120 px 放数据库名称（40 px 700 无衬线，和页面标题一样）和时间范围（16 px `--mb-muted`），四周留白 80 px）；样式与界面相同（第 1 节）；颜色：白色和透明背景用白天的颜色，“跟随主题”用当前模式的颜色和底色；PNG 按 2 倍输出为 3840 × 2160；SVG 的 `viewBox="0 0 1920 1080"`；背景可选“白色 / 透明 / 跟随主题”；文件名 `<数据库名>-时间脉络-YYYYMMDD.png/svg`（日期取本地日期）。条目太多放不下时，竖向缩小卡片行距，仍然一张图 |
| 没选日期属性 | 视图里内联提示“选择一个日期属性来生成时间脉络”和一个下拉框，不弹窗 |
| 没有带日期的记录 | 轻量提示“还没有带日期的记录”和“新建记录”按钮 |
| 未排期 | 底部“未排期 N 条”，点开是紧凑列表，点击打开记录 |

阶段段的边缘拖拽改时长、纵向时间线、演示模式全屏播放，v1 **不做**。

## 5. 汇总与状态的补充（WP-10 做，模板依赖）

- **状态分组**：状态属性的每个选项增加 `group` 字段，取值 `"todo" | "inProgress" | "complete"`（界面名：待办 / 进行中 / 完成），与 Notion 状态属性一致。迁移（schema v13）的默认规则，按顺序判断：选项 `id === "done"` 或名称含“完成”→ `complete`；`id === "doing"` 或名称含“进行”→ `inProgress`；其他 → `todo`。已有 `group` 且取值合法的保持不变。属性设置里可以修改每个选项的分组。
- **汇总新聚合方式**：`percent_checked`（复选框为真的比例）、`percent_complete`（状态属于 `complete` 分组的比例）、`count_unique`（去重计数）、`date_range`（最早日期 → 最晚日期）。百分比返回 0–1 的数字，显示为整数百分比（`62%`）；没有关联记录时显示空白（返回 `null`）。在回收站里的记录不计入。
- **双向关联**：在一侧添加或移除关联，另一侧（`reciprocalPropertyId`）自动同步。WP-10 开工时先写测试确认现状，缺失就补上。

## 6. “软件开发进程”模板

### 6.1 使用流程

侧栏“模板”→ 模板库 → 选中“软件开发进程”→ 右侧预览（插图 + 说明 + 包含的内容清单）→ 填写：项目名称（默认“新项目”）、放到哪个文件夹（默认当前文件夹）、“包含示例数据”（默认勾选）→ “使用模板” → 生成并打开页面。

### 6.2 生成的内容

**页面**：标题 `<项目名称> · 开发进程`，全宽，图标用图标库里的 `calendar-event`（若有更合适的“路线/旗帜”类图标可在报告里说明后替换）。正文依次是：

1. 标注块：`项目目标：在这里用一句话写下这个项目要解决什么问题。`
2. 标题 2「时间脉络」+ 数据库块：数据源“里程碑与阶段”，视图“时间脉络”。
3. 标题 2「进行中」+ 数据库块：数据源“任务”的关联视图，筛选 状态 属于“进行中”分组，列表视图。
4. 标题 2「全部任务」+ 数据库块：数据源“任务”，看板视图，按状态分组。
5. 标题 2「版本记录」+ 数据库块：数据源“里程碑与阶段”的关联视图，筛选 类型 = 发布，按 时间 降序，列表视图。

**数据源 A：里程碑与阶段**

### 6.4 模板的实现方式

- 内置模板是代码：`src/templates/builtin/softwareDevRoadmap.js` 导出 `{ id: "builtin.software-dev-roadmap", version: 1, name, description, category: "开发", preview, build(context) }`。
- `build({ now, idFactory, projectName, folderId, includeSampleData })` 返回 `{ pages, dataSources, databaseViews, databaseItems, relations }`，所有 ID 都来自 `idFactory`，所有日期都从 `now` 推算（本地日期，用同一个辅助函数 `localDateString(ms)` 计算，测试也用它）。
- `instantiateTemplate(workspace, template, options)` 把结果合并进工作区，返回 `{ workspace, rootPageId }`；合并后必须通过 WP-01 建立的 `checkWorkspaceIntegrity`（没有 error）。
- 同一模板用两次，得到两套互不相干的数据（ID 不重复，改一套不影响另一套）。
- 用户自己的页面模板（现有 `pageTemplates`）出现在模板库的“我的模板”分类里。
