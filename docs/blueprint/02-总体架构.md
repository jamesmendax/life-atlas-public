# 02 总体架构

本文件是架构决策的落地规格。WP 里写“按 02 第 X 节”时，指的就是这里。所有接口的完整签名在 `11-接口契约.md`。

## 1. 进程与窗口模型

```
┌──────────────────────── Electron 主进程（Node 24，可信区）────────────────────────┐
│ app 生命周期 · 单实例锁 · 数据目录 · 日志                                           │
│ WorkspaceStore（workspace.db）  AssetStore（assets/）  SnapshotService  BackupService │
│ VaultService（vault.db + 加密 + 自动上锁 + 剪贴板）   KDF Worker（Argon2id，独立线程）│
│ 协议：app://bundle/…（界面文件）  life-asset://<sha256>（附件）                      │
└──────────────▲───────────────────────────────────────────────▲────────────────────┘
               │ IPC（la:workspace:* / la:assets:* / la:backup:* / la:app:* / la:exports:*）│ IPC（la:vault:*，只认密钥库窗口）
┌──────────────┴──────────────┐                    ┌───────────────────┴──────────────┐
│ 工作区窗口（沙箱渲染进程）     │                    │ 密钥库窗口（沙箱渲染进程）          │
│ 现有 React + BlockNote 应用   │  不能调用任何       │ 独立入口 vault.html，体积小、       │
│ 渲染页面、数据库、导入的内容   │  la:vault:* 通道    │ 不渲染任何用户 HTML/Markdown        │
│ preload: window.lifeAtlas     │ ─────────────────▶ │ preload: window.lifeAtlasVault     │
└──────────────────────────────┘  只能“打开密钥库窗口” └──────────────────────────────────┘
                                   和读取 { exists, locked }
另有首次启动向导窗口（入口 setup.html，preload: window.lifeAtlasSetup，只在没有数据目录时出现，WP-05）。
```

规则：

1. 渲染进程一律 `sandbox: true`、`contextIsolation: true`、`nodeIntegration: false`。渲染进程拿不到 Node、文件系统和数据库。
2. 工作区窗口的 preload **不暴露**任何密钥库读写接口；和密钥库有关的只有 `app.openVaultWindow()`、`app.getVaultStatus()`、`app.onVaultStatusChanged()`（11 第 1 节）。
3. 主进程里每个 `la:vault:*` 处理函数第一步检查 `event.sender.id === vaultWindow.webContents.id`，不是就返回 `E_FORBIDDEN`。工作区与向导的通道同理，只接受各自的窗口。
4. 主进程是唯一能碰 SQLite 文件、附件文件和密钥的地方。

## 3. 数据目录（运行时）

```
<DataRoot>\                       例：D:\LifeAtlas\
  life-atlas.root.json            标记文件 { kind:"life-atlas-data-root", formatVersion:1, createdAt, createdByAppVersion }
  workspace.db (+ -wal, -shm)     工作区数据
  vault.db                        密钥库（全部密文，见 03）
  assets\ab\abcdef…(sha256)       附件文件，按内容哈希命名，无扩展名（ab 是哈希前两位）
  snapshots\<时间>-<原因>\         快照（04 第 6 节）
  backups\                        手动导出的默认位置（用户可另选）
  logs\                           日志，按天一个文件 YYYY-MM-DD.log，保留 14 天
  runtime\                        Electron/Chromium 的 userData、sessionData、crashDumps 都在这里
  asset-trash\                    附件回收站（WP-17）
  .lock                           目录锁 { pid, startedAt, appVersion }
```

- `bootstrap.json` 是唯一放在数据目录之外的文件：位置是 `<appData>\Life Atlas\bootstrap.json`（`appData` 用 `app.getPath("appData")` 取得，必须在修改 `userData` 之前读取）；内容 `{ "dataRoot": "D:\\LifeAtlas" }`。测试钩子开启时，环境变量 `LIFE_ATLAS_BOOTSTRAP_DIR` 可以替换这个目录（测试必须用它，不能写真实的 `%APPDATA%`）。
- **首次启动的默认建议**：若 `D:` 盘存在，建议 `D:\LifeAtlas`，否则 `%USERPROFILE%\Documents\LifeAtlas`；用户可改。
- 路径里含 `OneDrive`、`Dropbox`、`Google Drive`、`iCloud`、`坚果云`（不区分大小写）时，判定为“同步盘”，提示：“同步盘可能损坏正在使用的数据库，建议只把备份放到同步盘”，允许用户坚持。
- **安装目录**：打包版为 `path.dirname(process.execPath)`；开发版（未打包）没有安装目录限制。数据目录不能在安装目录内。
- 选择已有目录时，若既不是空目录也没有 `life-atlas.root.json`，拒绝使用（防止误把数据写进别的文件夹）。
- **`.lock` 规则**：用 `fs.openSync(path, "wx")` 独占创建并写入 `{ pid, startedAt, appVersion }`。已存在时读出 `pid`：若 `pid !== process.pid` 且该进程还活着（`process.kill(pid, 0)` 不抛错），判定为“正被另一个 Life Atlas 使用”；否则视为上次异常退出留下的旧锁，覆盖它并写日志 `lock.stale-recovered`。正常退出时删除 `.lock`。
- 环境变量 `LIFE_ATLAS_DATA_ROOT` 优先于 bootstrap。**测试和开发必须用它指向临时目录或 `<repo>\.devdata\`**，永远不碰用户真实数据目录。

### 3.1 主进程启动顺序（`electron/main/index.js`，WP-03 建立，之后各 WP 只在标明的位置插入）

1. 读取 `flavor` 与“测试钩子是否开启”（第 10 节）。
2. 解析数据目录（只读）：`LIFE_ATLAS_DATA_ROOT` → bootstrap.json → 开发版默认 `<repo>\.devdata` → 都没有则进入“首次启动模式”。
3. 设置路径（必须在 `app.whenReady()` 之前）：
   - 有数据目录：`userData`、`sessionData` 设为 `<DataRoot>\runtime`，`crashDumps` 设为 `<DataRoot>\runtime\crashes`；
   - 首次启动模式：三者都设为 `<系统临时目录>\life-atlas-setup\`（退出时删除）。
4. `app.requestSingleInstanceLock()`（单实例锁以 `userData` 为准，所以必须在第 3 步之后）。拿不到就 `app.quit()` 并结束，不弹任何框。
5. 有数据目录时：确认或创建 `life-atlas.root.json`，获取 `.lock`。`.lock` 被占用 → `dialog.showErrorBox("数据目录正在使用", "这个数据目录正被另一个 Life Atlas 使用。")` 后 `app.exit(1)`（`showErrorBox` 可以在 ready 之前调用）。
6. `protocol.registerSchemesAsPrivileged(...)`（必须在 ready 之前）。
7. `await app.whenReady()`。
8. 在 `session.defaultSession` 上安装协议、CSP、网络拦截、权限拒绝（第 7 节）；测试钩子开启时安装 `testHooks.js`。WP-20 起，接着调用 `Menu.setApplicationMenu(null)` 和 `installThemeBackgroundSync()`（第 7 节“菜单栏与窗口底色”），都在创建第一个窗口之前。
9. 首次启动模式：打开向导窗口（WP-05；WP-03 里先用 `dialog.showErrorBox` 提示“未找到数据目录”并退出）。否则：打开工作区数据库（WP-04 起）→ 创建工作区窗口。
10. `second-instance` 事件：恢复并聚焦已有的工作区窗口。
11. 退出：`before-quit` 时请求渲染进程保存（WP-04）、密钥库上锁（WP-06）、关闭数据库、删除 `.lock`。

## 4. 工作区存储（workspace.db）

### 4.1 表结构

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = FULL;          -- 个人资料库：宁慢勿丢
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;

CREATE TABLE IF NOT EXISTS meta (
  key   TEXT PRIMARY KEY,           -- 见下方 meta 键清单
  value TEXT NOT NULL               -- JSON 字符串
);
CREATE TABLE IF NOT EXISTS entities (
  collection TEXT NOT NULL,         -- 必须在白名单内（4.2）
  id         TEXT NOT NULL,
  json       TEXT NOT NULL,         -- 整个实体的 JSON
  updated_at TEXT NOT NULL,
  PRIMARY KEY (collection, id)
) WITHOUT ROWID;
CREATE TABLE IF NOT EXISTS assets (
  sha256        TEXT PRIMARY KEY,
  size          INTEGER NOT NULL,
  mime          TEXT NOT NULL,
  original_name TEXT,
  created_at    TEXT NOT NULL
);
```

meta 键清单（值都是 JSON 字符串）：

| 键 | 含义 | 引入 WP |
| --- | --- | --- |
| `schemaVersion` | 数字 | WP-04 |
| `workspaceId` | `ws-<uuid>` | WP-04（值来自工作区对象，见 4.3） |
| `savedAt` | 上次保存时间 | WP-04 |
| `ui` | 整个 `ui` 对象 | WP-04 |
| `generation` | `gen-<uuid>`，数据库创建时生成，每次恢复备份或快照后更换 | WP-04 |
| `extras` | 工作区对象里 13 个集合与 `schemaVersion`、`workspaceId`、`savedAt`、`ui` 以外的其他顶层字段（原样保存，没有就是 `{}`；与备份包 `meta.json` 的 `extras` 同义） | WP-04 |
| `lastFullBackupAt` | 上次成功导出完整备份的时间（不进备份包） | WP-05 |
| `lastAppVersion` | 上次打开这个数据目录的应用版本（用于 `pre-upgrade` 快照） | WP-05 |

后续 WP 新增表或 meta 键必须先写进本节，不得自行添加。

### 4.2 集合白名单

`folders, pages, dataSources, databaseItems, databaseViews, relations, syncedSources, attachments, people, pageTemplates, databaseTemplates, discussions, comments`

已规划的新增集合：`pageVersions`（WP-16 起加入白名单与备份包）。其他新增集合必须先由总设计师修订本节。`ui` 存在 `meta.ui`，不进 entities（收藏、最近访问、提醒状态、工作区名称等都在 `ui` 里，随备份一起导出）。

### 4.3 加载、保存与迁移

- **加载规范化（浏览器与桌面共用）**：`src/persistence/normalize.js` 导出纯函数 `normalizeLoadedWorkspace(input, { fallbackWorkspace, now, idFactory })`（WP-01 建立，WP-02 增加 `workspaceId`）。它做现在浏览器适配器 `migrateWorkspace` 做的全部事情：补页面默认字段、规范化 `ui.assetPreferences`、调用 `upgradeWorkspace`、清理到期回收站（`src/domain/trash.js` 的 `purgeExpiredTrashGroups(workspace, now)`，WP-01 建立）；另外在缺少 `workspaceId` 时用 `idFactory("ws")` 生成。迁移函数本身保持纯函数，不生成随机 ID。
- **桌面加载流程**（主进程）：打开数据库 → `PRAGMA quick_check` 必须为 `ok` → 读出全部行组装成 workspace 对象（形状见 11 第 4.2 节）→ 若 `schemaVersion < CURRENT_SCHEMA_VERSION`，先做 `pre-migration` 快照 → `normalizeLoadedWorkspace(...)` → 把规范化前后有变化的实体（按 JSON 字符串比较）和 meta **在一个事务里写回** → 返回 `{ workspace, generation }`。这样迁移和到期清理的结果都落到数据库里，渲染进程拿到的就是数据库里的内容。
- **启动顺序（渲染进程）**：`src/main.jsx` 先 `await repository.load()`，拿到数据后再渲染 `<App repository={repository} initialWorkspace={workspace} />`；加载期间显示极简启动画面。`App.jsx` 不再在模块顶层创建 repository。首次渲染出数据后，在 `<html>` 上设置 `data-la-ready="1"`（端到端测试与性能计时都以它为“可交互”标志）。
- **保存**：渲染进程保留“上次已保存”的每个集合的 `Map(id → 实体引用)`。因为状态更新是不可变的，没变的实体引用不变，所以只需按引用比较就能得到增量 changeset（形状见 11 第 4.1 节）。主进程先比较 `generation`，不一致返回 `E_CONFLICT`；一致则在一个事务里执行全部 upsert/delete，并更新 `meta.savedAt`、`meta.ui`、`meta.schemaVersion`。保存失败时界面显示“保存失败，正在重试”，保留增量，3 秒后重试。
- **防抖**：保持现有 450 ms。窗口关闭/应用退出时，主进程发 flush 请求（11 第 1 节 `app.onFlushRequest`），渲染进程立即保存并回执；主进程最多等 3 秒。
- **校验**：主进程校验每个 upsert：集合在白名单内、`id` 是 1–200 字符的字符串、`json` 能解析成对象且其 `id` 与行 `id` 相同、单个实体不超过 20 MB。校验失败整批拒绝，返回 `E_INVALID_ARGUMENT`。
- **读取失败保护**：数据库打不开、`quick_check` 不是 `ok`、JSON 解析失败时，主进程进入“只读错误”状态：`load` 返回 `E_CORRUPT`，`applyChanges` 一律拒绝，**不修改**数据库文件。界面提示“数据无法读取，请从快照或备份恢复”。
- **完整检查**：`PRAGMA integrity_check` 比 `quick_check` 慢，只在创建每日快照时对快照副本执行（04 第 6 节）。

### 4.4 新建空白工作区

桌面版首次创建的工作区**不能**写入 `workspaceSeed.js` 里的示例数据。只创建：一个文件夹“我的空间”，里面一个页面“开始使用 Life Atlas”（内容见 WP-04 第 3.4 节）。示例数据只留给浏览器开发模式和测试夹具。

## 5. 附件存储（AssetStore）

- **写入**：`put(bytes, { mime, name })` → 计算 SHA-256 → 若 `assets/<前两位>/<sha256>` 不存在，先写临时文件再改名 → 插入 `assets` 表 → 返回 `{ assetId: sha256, url: "life-asset://" + sha256 }`。同一文件重复上传只存一份。
- **读取**：协议 `life-asset://<64位小写十六进制>`；格式不对返回 400；不存在返回 404；查表得到 MIME；响应头带 `Content-Type`、`X-Content-Type-Options: nosniff`、`Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; img-src data:`。`text/html` 一律改为 `text/plain` 返回。
- **不可变**：附件写入后不修改；v1 **不做自动清理**未引用附件（避免误删），WP-17 只提供“预览可清理的附件”和手动确认清理。
- **大小**：单文件上限 1 GB；超过 200 MB 时提示确认。
- **引用方式**：工作区里所有本地二进制统一用字符串 `life-asset://<sha256>` 引用（页面图标、封面、编辑器图片/文件块的 `url`、附件实体）。附件实体 `provider` 新增取值 `"asset"`，`storageKey` 存 sha256（schema v12，WP-04）。
- **远程地址**：`http(s)://` 的图片、视频、音频和文件**不加载**：编辑器的 `resolveFileUrl` 把它们换成本地生成的“外部内容（未加载）”占位图（WP-14），双击后经主进程确认用系统浏览器打开。WP-14 之前，这类请求由网络拦截取消（WP-03）。

## 6. IPC 约定

- 通道名、调用方式、返回格式、发送方校验：见 `11-接口契约.md` 开头的规则。
- 返回值统一：`{ ok: true, value }` 或 `{ ok: false, error: { code, message, retryAfterMs? } }`。不把异常对象直接抛过 IPC。
- 错误码：`E_INVALID_ARGUMENT`、`E_FORBIDDEN`、`E_NOT_FOUND`、`E_LOCKED`、`E_BAD_PASSWORD`、`E_THROTTLED`、`E_CORRUPT`、`E_IO`、`E_CONFLICT`、`E_UNSUPPORTED_VERSION`、`E_CANCELLED`。
- `E_LOCKED` 可以带原因：`message` 取 `"locked"` 或 `"recovery-unconfirmed"`。
- 三个窗口能用的全部函数见 11 第 1–3 节，**不得新增**。

## 7. 安全基线（所有窗口都适用）

```js
webPreferences: {
  preload, sandbox: true, contextIsolation: true, nodeIntegration: false,
  nodeIntegrationInWorker: false, webSecurity: true, allowRunningInsecureContent: false,
  experimentalFeatures: false, webviewTag: false, navigateOnDragDrop: false,
  spellcheck: false,          // Electron 拼写检查会联网下载词典，必须关闭
  devTools: !app.isPackaged,  // 打包版（test 和 release）一律没有开发者工具，没有任何环境变量可以打开
}
```

- **加载方式**：用自定义协议 `app://bundle/<入口>.html`（`registerSchemesAsPrivileged`，`standard + secure + supportFetchAPI`），映射到 `dist/client`（打包版在 asar 内，开发版在仓库的 `dist/client`）；不用 `file://`。只有设置了 `LIFE_ATLAS_DEV_URL` 的开发版才加载 Vite 开发服务器 `http://127.0.0.1:<端口>`。
- **CSP**（工作区窗口与向导窗口）：
  `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' life-asset: data: blob:; media-src 'self' life-asset: blob: data:; font-src 'self' data:; connect-src 'self' life-asset:; object-src 'none'; frame-src 'none'; base-uri 'none'; form-action 'none'`
- **CSP**（密钥库窗口）：`default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; connect-src 'none'; object-src 'none'; frame-src 'none'; base-uri 'none'; form-action 'none'`
- CSP 通过 `app://` 协议响应头下发。加载 Vite 开发服务器时没有 CSP（热更新需要内联脚本），所以**安全相关的端到端测试必须跑在 `app://` 上**（未打包但不设 `LIFE_ATLAS_DEV_URL`，或打包后的测试版）。
- **导航**：`will-navigate` 按窗口白名单拦截：工作区窗口只能停留在 `app://bundle/index.html`（含 `#` 路由），密钥库窗口只能是 `vault.html`，向导窗口只能是 `setup.html`；工作区窗口**不能**导航到 `vault.html`。`setWindowOpenHandler` 一律 `deny`，http(s) 链接改走 `app.openExternal` 的确认流程。
- **密钥库窗口使用独立的内存会话**：`webPreferences.partition = "vault"`（没有 `persist:` 前缀，任何缓存和存储都不写磁盘）。自定义协议、CSP 响应头、网络拦截、权限拒绝都要在 `session.fromPartition("vault")` 上**再注册一次**，否则不生效。
- **权限**：`setPermissionRequestHandler` 与 `setPermissionCheckHandler` 默认全部拒绝；工作区窗口只允许 `clipboard-sanitized-write`。
- **网络拦截**：`session.webRequest.onBeforeRequest` 取消所有 `http/https/ws/wss` 请求；只有加载 Vite 开发服务器时放行 `127.0.0.1:<该端口>`。被取消的请求写一条日志（只记主机名）。
- **下载**：`will-download` 只接受 `blob:` 和 `data:` 来源（页面导出用），弹出系统保存对话框。
- **单实例**：见第 3.1 节第 4 步。
- **菜单栏与窗口底色**（WP-20 起）：所有窗口都没有菜单栏（`Menu.setApplicationMenu(null)`；复制、粘贴、撤销、全选这些编辑快捷键由 Chromium 自己处理，不受影响）。每个窗口创建时传 `backgroundColor: themeBackgroundColor()`（`electron/main/windows.js`：夜间 `#191919`、白天 `#ffffff`，即 12 第 3 节的 `--mb-paper`），夜间启动时不会先闪一下白色；`installThemeBackgroundSync()` 在 `nativeTheme` 变化时更新全部已打开的窗口。向导窗口（WP-05）和密钥库窗口（WP-07）同样这样创建。
- **日志**：只记录事件名、实体 ID、数量和错误码；**永远不记录**页面内容、标题、密码、密钥条目字段。
- **加固项**（Electron Fuses、ASAR 完整性校验）在 WP-11 做，只作用于 release 构建（第 10 节）。

## 8. 浏览器模式与桌面模式

- 渲染进程用 `window.lifeAtlas?.platform === "desktop"` 判断运行环境，**不要**用 UA 判断。
- 浏览器模式（`npm run dev`）：继续用 localStorage 适配器，只用于界面开发和浏览器场景测试；密钥库入口显示“仅桌面版可用”，不提供任何密钥功能。
- 浏览器模式保留“导出完整备份”（WP-02），这是把用户现有浏览器数据迁到桌面版的唯一通道。
- `.openai/hosting.json`、`worker/index.js`、`scripts/prepare-sites-build.mjs`、`tests/sites-worker.test.mjs` 保持原样不删；`npm run build` 的现有产物位置不变（桌面打包复用 `dist/client`）。
- **用户真实数据所在的浏览器地址**是 `localhost:4173` / `127.0.0.1:4173`（以及可能的 4175）。执行者**不得**在这些端口启动任何服务，不得用用户自己的浏览器或浏览器配置打开预览。需要看界面时，只用 Playwright 启动的全新浏览器上下文和 5178 端口。

## 10. 构建、打包与构建类型（flavor）

- `electron` 固定为 `44.4.5`（不加 `^`），优先使用本机缓存，避免重复下载。
- 打包用 `electron-builder`（开发依赖），配置文件 `electron-builder.yml`；`appId: com.medax.lifeatlas`，`productName: Life Atlas`；产物放 `release/`（已在 `.gitignore`）。
- **三种构建类型**：

  | flavor | 怎么得到 | 用途 | 测试钩子 | Fuses（WP-11） |
  | --- | --- | --- | --- | --- |
  | `dev` | 未打包（`app.isPackaged === false`） | 开发、大部分端到端测试 | `LIFE_ATLAS_TEST=1` 时开启 | 无 |
  | `test` | `npm run desktop:build:test` → `release/test/win-unpacked/` | 需要打包特性的端到端测试 | `LIFE_ATLAS_TEST=1` 时开启 | **不加**（Playwright 需要调试参数） |
  | `release` | `npm run desktop:build` → `release/release/`（NSIS 安装包 + `win-unpacked`） | 给用户安装 | **永远关闭**，任何环境变量都打不开 | 加 |

- flavor 的判断（`electron/main/flavor.js`）：未打包为 `dev`；打包后读取 `app.getAppPath()` 下 `package.json` 的 `lifeAtlasFlavor` 字段（打包脚本用 electron-builder 的 `extraMetadata` 写入），等于 `"test"` 为 `test`，其他一律为 `release`。
- **测试钩子开启** = `process.env.LIFE_ATLAS_TEST === "1"` 且 flavor 不是 `release`。11 第 5 节的全部钩子和测试用环境变量都只在这时生效。
- 脚本：`desktop:dev`、`desktop:build`（release）、`desktop:build:test`（test，只出 `dir` 目标）、`test`、`test:e2e:desktop`。现有脚本保留。
